# 凭据与进程边界

旧 GUI 把密码拼接进 `--password` 参数，任何能够查看进程命令行的同用户程序都可能读到它；旧账号 JSON 也直接保存密码。3.0.0 同时处理传递和持久化两个位置。

- GUI 使用 `ArgumentList` 为每个非秘密参数创建独立边界，账号或路径中的引号不会变成额外选项。密码只写入重定向标准输入的一行，写完关闭；包含换行/NUL 的密码会在进程启动前拒绝。
- 密码使用 DPAPI `CurrentUser` 保护后才序列化。先在内存完成所有保护操作，再在同目录写临时文件并原子替换；不保存明文备份，也不通过默认值吞掉解密错误。
- 默认配置在当前用户的 LocalAppData；旧 JSON 只有在新加密文件保存完成后删除。旧文件被删除不等于 SSD、文件历史、备份中的旧数据已被安全擦除；已有副本需要用户自行清理。
- 核心路径固定为 GUI 安装目录，禁止通过 PATH 搜索陌生同名程序。初始化检查安全输入能力，不支持时要求升级，不退回 `--password`。
- 进程输出和错误输出并行读取，密码值在进入日志缓冲前隐藏；诊断导出还隐藏当前账号。日志缓冲限制条数及单行长度，避免长时间运行无限占用内存。
- 生命周期另用随机命名、`CurrentUserOnly` 的私有 Named Pipe：只传固定 `stop\n` 控制消息，绝不传密码。取消认证或关闭 GUI 时先请求注销并等待最多 2 秒，超时再结束当前拥有的核心进程树；GUI 崩溃或断开管道时核心会收到 EOF 并进入注销退出。不会枚举并终止其他同名核心，不使用 `Thread.Abort`。

DPAPI 防止离线读取配置文件直接得到密码，不保护已控制当前 Windows 用户会话的恶意程序。WPF PasswordBox 与 Rust MD5 认证最终需要内存中的密码；本实现不声称内存中不存在明文，不改变原有 EAP/DrCOM 协议。

无线 Portal 的传输安全单独由 URL 协议决定：stdin 与 DPAPI 不会把远端 HTTP 变成加密连接。界面默认拒绝 HTTP，必须由用户显式允许；HTTPS 不回退 HTTP，API 必须同主机。未勾选 HTTP 时还显式传入 `--require-https-portal`，避免旧核心配置开启 HTTP。模式始终通过 CLI 显式指定，有线完整模式使用 `--with-udp`，避免旧 `core.yml` 将用户选中的有线模式变成其他提供者。门户 URL 的 userinfo 和片段禁止使用；查询参数只接受与核心一致的公开接入点发现字段白名单，解码后的未知字段、密码/令牌/会话参数均禁止进入配置或进程参数；错误消息不回显 URL 或秘密值。
