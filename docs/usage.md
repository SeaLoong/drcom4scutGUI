# 安装与日常使用

[返回首页](../README.md)

第一次使用请按[首页的安装和登录步骤](../README.md#安装)操作。本页补充各系统的安装细节、无线网页登录、多账号和排障方法；不需要从头理解所有网络设置。

## 安装和系统要求

安装时需要两个下载包：**GUI 是操作窗口，核心负责实际认证**。两者都要选与你的系统、处理器相符的包。GUI 自带运行所需组件，不用另外安装 .NET；但不包含核心。

目前本文介绍的跨平台版本通过 **Pre-release（预发布）**提供。可从[当前 GUI 跨平台预览](https://github.com/SeaLoong/drcom4scutGUI/releases/tag/preview-11-1-0416bf21)开始，或在 [GUI 全部版本](https://github.com/SeaLoong/drcom4scutGUI/releases)中找 3.1.0 或更新版本。再到[核心文件列表](https://github.com/SeaLoong/drcom4scut/releases)下载 0.5.0 或更新的兼容核心。请核对所需系统包是否存在，不要直接选发布页第一项、旧正式版或 `Source code` 源码。

### 下载哪一个核心包

Windows 在“设置 → 系统 → 关于”查看“系统类型”；Mac 在“苹果菜单 → 关于本机”查看“芯片”或“处理器”。Intel、AMD 的普通电脑通常选 x64；Apple 芯片和 Windows ARM 电脑选 ARM64。Linux 可在终端运行 `uname -m`：`x86_64` 对应 x64，`aarch64` 对应 ARM64。

下表列出文件名中应包含的部分，前面还会有项目名和版本号。

| 电脑 | GUI 包 | 核心包 |
| --- | --- | --- |
| Windows，Intel / AMD | `win-x64.zip` | `x86_64-pc-windows-msvc.zip` |
| Windows，ARM64 | `win-arm64.zip` | `aarch64-pc-windows-msvc.zip` |
| Mac，Intel | `osx-x64.tar.gz` | `x86_64-apple-darwin.tar.gz` |
| Mac，Apple 芯片 | `osx-arm64.tar.gz` | `aarch64-apple-darwin.tar.gz` |
| Linux，Intel / AMD | `linux-x64.tar.gz` | `x86_64-unknown-linux-gnu.tar.gz` |
| Linux，ARM64 | `linux-arm64.tar.gz` | `aarch64-unknown-linux-gnu.tar.gz` |

请解压整个 GUI 包，不要只拿走其中一个程序文件。下载后可用同一发布页的 `SHA256SUMS` 检查文件是否完整：它是每个压缩包对应的校验值。Windows 可用 `Get-FileHash 文件名 -Algorithm SHA256`，Mac 用 `shasum -a 256 文件名`，Linux 用 `sha256sum 文件名`，将结果与清单对应行比较。

### Windows

推荐使用当前受支持的 Windows 11 系统。解压后，将核心 `drcom4scut.exe` 复制进 GUI 文件夹，使它们像这样放在一起：

```text
校园网客户端文件夹/
├── drcom4scutGUI.exe
├── drcom4scut.exe
└── GUI 包中的其他文件……
```

有线认证还需安装与你的系统相符的 [Npcap](https://npcap.com/#download)。安装后，核心才能收发校园网认证所需的网络报文。然后以普通用户打开 `drcom4scutGUI.exe`。无线网页登录不需要 Npcap。

### macOS

GUI 支持 **macOS 15 或更新且仍受 .NET 10 支持的系统**，参见[官方系统列表](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)。核心程序单独的系统要求不能用来判断 GUI 是否可运行。

Apple 芯片 Mac 选择 ARM64 包，直接运行，不需要 Rosetta。将解压后的核心与应用放在同一个文件夹：

```text
校园网客户端文件夹/
├── drcom4scutGUI.app
└── drcom4scut
```

双击 `.app` 打开。**不要将核心放进 `.app` 内部；移动程序时也要带上旁边的核心。**

首次打开可能被 macOS 拦截，因为当前应用尚无 Apple Developer ID 签名和公证。应用有用于检查完整性的本地签名（ad-hoc），但这不等于 Apple 已审核它。核对下载来源和校验值后，按 Apple 的[允许打开单个应用的方法](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac)，到“系统设置 → 隐私与安全性”中允许这份程序，不必关闭整个系统的安全检查。核心是独立程序，也可能需要单独允许。若 GUI 能打开但核心被拒绝，可在核心所在文件夹的终端运行 `./drcom4scut --version`，按系统提示允许这份核心，再重试 GUI；步骤见[核心首次运行说明](https://github.com/SeaLoong/drcom4scut/blob/master/docs/macos.md#下载与首次运行)。

有线认证还需要允许核心访问系统的网络报文设备，也叫 **BPF 权限**。按[核心 macOS 指南](https://github.com/SeaLoong/drcom4scut/blob/master/docs/macos.md#有线抓包权限)完成一次授权，再以普通用户打开 GUI；不要用 `sudo` 打开 GUI。无线网页登录不需要这项授权。

### Linux

Linux 包适用于带图形桌面的常见发行版，例如 Ubuntu 22.04 / 24.04。它们不是 OpenWrt 路由器上的图形程序；路由器请使用[独立核心与路由器管理页](https://github.com/SeaLoong/drcom4scut/blob/master/docs/openwrt.md)。

将解压后的核心 `drcom4scut` 放进 GUI 文件夹，保留包中其他文件，然后打开 `drcom4scutGUI`，或在该目录的终端运行：

```sh
./drcom4scutGUI
```

程序需要 X11 图形支持；使用 Wayland 桌面时，需要系统提供 XWayland。即使程序自带 .NET，系统仍须有绘图库和字体。Ubuntu 24.04 缺少这些组件时，可以安装：

```sh
sudo apt install libx11-6 libice6 libsm6 libxcb1 libxrandr2 libxi6 \
  libxcursor1 libxrender1 libgl1 libfontconfig1 libgtk-3-0t64 \
  libicu74 libssl3t64 fonts-noto-cjk
```

其他发行版使用对应包名。中文变成方框时，先安装中文字体；上面的 `fonts-noto-cjk` 即为其中一种。更多系统依赖见 [Avalonia 的 Linux 说明](https://docs.avaloniaui.net/docs/supported-platforms#desktop-linux)与 [.NET 系统列表](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)。这些包面向 glibc 桌面，不能直接用在 musl 系统上。

“记住密码”还需要系统的桌面密码库。Ubuntu 可安装 `libsecret-tools`，它提供 `/usr/bin/secret-tool`；同时须有可用、已解锁的 Secret Service 密码库。只安装命令行工具不等于密码库已准备好。暂时无法保存密码时，可取消“记住密码”后认证。

GUI 使用普通用户运行。有线认证需要管理员给已核对、可信的核心授予收发认证报文的权限。可在已解压的 GUI 文件夹中执行：

```sh
sudo setcap cap_net_raw=ep ./drcom4scut
getcap ./drcom4scut
./drcom4scut doctor
```

这里的 `cap_net_raw` 是 Linux 对这项权限的名称，只授予核心，不要授予 GUI。若系统没有 `setcap`，Ubuntu 可先安装 `libcap2-bin`。`getcap` 用来确认权限是否写入，`doctor` 用来检查运行条件；电脑有多个网卡时，可按自检提示再指定实际网卡。完成后打开 GUI，点击“环境自检”确认。更新替换核心后需重新检查并授权。受管理的校园或办公设备应按管理员策略设置，不能自行更改时请联系管理员。无线网页登录不需要这一步。

## 有线认证

1. 将电脑连上校园网线，在系统网络设置里确认有线连接已启用。
2. 打开 GUI，在“模式”中选择“有线 EAP + UDP”。这是默认的完整有线登录方式。
3. 填写校园网账号和密码。若学校要求账号带后缀，按学校要求填写完整账号。
4. “网卡”先用“自动选择”；选错时改为实际插着校园网线的以太网卡。“本机源 IP”通常留空。
5. 按需要勾选“记住密码”，点击“认证”。

窗口会显示当前进度。完整有线模式需要学校先接受身份认证，再完成持续在线确认，所以只看到“802.1X 已通过”时还应继续等待。界面显示“认证和 UDP 心跳均成功”表示这两步均已完成。

“有线仅 EAP”省略后续在线保活步骤，只适用于已确认不需要完整流程的网络。不要为了让错误提示消失就切换它。

网卡列表可能同时有无线网卡、虚拟网卡；插网线时应选择实际的以太网接口。程序负责校园网登录，不负责向系统申请或修改 IP 地址。

## 无线 Portal

### 这与浏览器登录有什么关系

校园 Wi-Fi 通常是：**先连上无线网络，再在校园网页填写账号、密码，点击登录。** 其中网页这一步也叫“门户登录”，界面用英文 **Portal** 标识。它与插网线时的认证方式不同。

本工具尝试自动发送特定 DrCOM/ePortal 校园网页使用的登录请求，并查询学校是否确认当前设备在线。它不打开或控制浏览器，也不会替系统连接 Wi-Fi。浏览器手动登录仍是正常使用方式；如果你不需要自动化，直接使用校园网页即可。

无线实现参考了其他公开校园网客户端，具体来源见[核心的参考记录](https://github.com/SeaLoong/drcom4scut/blob/master/docs/references-clients.md)。现有自动检查使用模拟网页服务，**尚未在实际校园网验证，不代表支持所有校区或所有登录页**。需要验证码、短信、扫码或统一身份认证跳转的页面，不能指望仅填一个网址就能使用。

### 尝试自动登录

1. 在系统中连接校园 Wi-Fi。
2. 用浏览器打开校园提供的登录页，确认这是你通常使用的页面，并核对其地址。首次配置时，也可先确认账号能在浏览器中正常登录。
3. 在 GUI 选择“无线 Portal”，填写校园账号、密码，将**尚未填写账号密码的学校登录页面**地址填入“门户地址”。不要使用网上随手找到的示例域名，也不要复制提交后的长登录请求。
4. “API 地址”“AC IPv4”“载荷 IPv4”“本机源 IP”先留空。
5. 核对下面的 HTTP 说明，再点击“认证”。只有学校确认当前设备在线后，界面才显示“无线门户已确认在线”。

不要复制已经带有账号、密码、令牌或会话信息的网址。学校入口中公开的网络定位参数可以保留；程序拒绝不支持的查询参数时，应核对入口，而不是把凭据塞进网址中。

地址以 `https://` 开头时，传输会检查服务器证书并加密。若学校实际只提供 `http://`，只有确认地址确实来自学校、并接受账号密码会在网络中明文传输后，才勾选“允许 HTTP 门户明文网络传输”。程序不会因为 HTTPS 失败就自动改用 HTTP。本机记住密码的保护不能改变这项网络风险。

点击“停止”会请求注销并停止程序重连，但**不等于在学校网页解除设备绑定或关闭自动登录**。学校侧若另有自动登录，设备可能再次上线；需要持续退出时，请在官方网页检查并关闭相应设置。

### 浏览器能用，程序不能用怎么办

先继续使用浏览器。可能是当前页面的登录过程与本程序支持的方式不同，也可能是入口、账号后缀或网络定位信息有误。

查看窗口下方的错误信息，记录程序版本、当前校区和错误类别。需要帮助时，可提供学校公开的登录页地址；不要提供含密码的登录请求、浏览器会话信息或私人抓包。分享诊断前按[隐私说明](security.md#导出和分享诊断)检查内容。

### 高级：无线地址字段

仅在学校提供了这些信息，或已明确定位问题时填写。不要猜数值，也不要照抄另一台设备的地址。

| 界面字段 | 普通含义 | 何时改 |
| --- | --- | --- |
| 门户地址 | 浏览器中校园登录页的可信入口 | 必须按当前学校入口填写 |
| API 地址 | 登录页向后台提交请求的地址 | 默认推导不适用时；必须与入口为同一主机 |
| AC IPv4 | 校园接入设备的地址 | 学校入口和查询都无法提供时 |
| 载荷 IPv4 | 学校登录系统识别的这台设备地址 | 自动查询结果不可用时 |
| 本机源 IP | 电脑实际用来发出请求的本地地址 | 电脑有多个地址，且确实需固定出口时 |

学校看到的地址与电脑本地地址可能不同，例如经过路由器时。修改“载荷 IPv4”不会改变电脑实际的网络出口。HTTPS 入口不能降级为 HTTP API，API 地址也不能换到另一个主机。

## 多账号

| 想做什么 | 操作 |
| --- | --- |
| 添加账号 | 在账号框输入新账号和密码，再点击“认证” |
| 切换账号 | 先停止认证，再从账号下拉框选择已保存的账号，点击“认证” |
| 修改保存的密码 | 选中账号，填写新密码，按需要勾选“记住密码”，再点击“认证” |
| 删除本机记录 | 先停止认证，选中账号，点击“删除”并确认 |

“记住密码”分别对每个账号生效。取消后仍可保存账号和网络设置，但下次打开程序时需要重新输入密码。删除本机记录不会删除学校侧账号。

更换电脑、配置损坏或密码无法恢复时，见[账号与隐私](security.md)。

## 托盘、停止和退出

Windows 右下角的小图标区域称为“托盘”；macOS 对应顶部菜单栏图标。认证成功后，这两个系统会在图标可用时收起窗口，认证仍在继续。右键或点击图标菜单，再选“打开”可找回窗口。Linux 保留普通窗口，避免桌面没有托盘时找不到入口。

连接中断时，窗口会重新显示相应状态，核心继续尝试恢复，不需要反复点击“认证”。

- 点击“停止”：请求注销，并停止本次重连；无线的学校自动登录设置需另行检查。
- 最小化或收起窗口：继续联网。
- 关闭窗口或选择托盘菜单“退出”：停止认证并关闭 GUI。

程序会先给核心正常注销的时间，超时才结束自己启动的进程，不会按程序名称关闭另一个独立运行的客户端。

## 自动启动和自动认证

这两个选项各管一步：

| 选项 | 作用 |
| --- | --- |
| 登录系统时启动 | 下次登录电脑时打开 GUI |
| 打开 GUI 后自动认证 | GUI 打开后，使用已选账号和当前模式开始登录 |

需要登录电脑后自动上网时，两项都勾选，并记住所选账号的密码。只选第一项会打开窗口但不认证；只选第二项仍需自己打开程序。

启动设置仅影响当前系统用户，不会安装系统级服务。Mac 在下次登录时生效，不会因勾选选项而立即再打开一个窗口。移动安装文件夹后，应重新设置启动选项，让它指向新的位置。

## 排查连接问题

1. 点击“环境自检”，按报告检查核心程序、网卡、地址和权限。
2. 有线确认网线与网卡；无线先确认浏览器是否能按平时的方法登录。
3. 查看窗口下方日志，判断卡在哪一步。一次失败后程序可能还在重试。
4. 需要求助时点击“导出诊断”，先检查私人信息，再附版本、系统和操作经过。

自检显示“部分运行条件尚未满足”时，按报告处理即可，不代表自检程序崩溃。自检通过也只说明电脑侧条件正常，不能替学校服务器接受账号。

## 高级：核心配置

普通使用只需操作窗口。确有额外要求时，可在停止认证后修改 GUI [配置目录](security.md#保存了哪些内容)中的 `core.yml`，字段含义见[核心配置参考](https://github.com/SeaLoong/drcom4scut/blob/master/docs/configuration.md)。不要在其中填写账号密码，GUI 会提供本次登录所需的凭据。

`profile` 是有线报文的兼容选项，默认 `legacy`，通常无需修改，也不按 Windows / Mac / Linux 来选择。GUI 没有对应的选择框；只有已确认学校服务端要求不同报文时才调整。

界面选择的有线或无线模式、是否使用完整有线流程、是否允许 HTTP 和填写的对应地址都会明确传给核心。不要依赖 `core.yml` 将界面显示的模式改成另一种，或绕过未勾选的 HTTP 许可。
