# 详细使用

[返回首页](../README.md)

## 有线认证

1. 将电脑连接到校园网以太网，启动 GUI。
2. 选择“有线 EAP + UDP”，填写账号和密码。
3. 网卡可以先选“自动选择”。若选错网卡，改为实际连接校园网的以太网卡。
4. 本机源 IP 通常留空；只有需要固定使用某个本机 IPv4 时才填写。
5. 点击“认证”，观察状态和日志。

完整有线模式先完成 802.1X，再建立 UDP 会话与心跳；两者都成功后才显示成功并收起窗口。“有线仅 EAP”只验证 802.1X，不建立 UDP 会话，适用于已经确认不需要 UDP 的网络。

界面的认证阶段和在线提示来自本次核心会话的状态。日志用于排查问题，日志中出现“成功”文字不等于本次连接已经在线。

网卡列表也可能出现无线或虚拟适配器。有线认证应选择与校园网实际相连的以太网接口；网卡选择和 IP 选择错误都可能导致认证失败。

## 无线 Portal

先连接校园无线网络，再选择“无线 Portal”。填写明确可信的门户地址，不要把陌生网页或下载地址当作认证门户。GUI 不会自动猜测门户主机。

| 字段 | 用途 | 通常如何填写 |
| --- | --- | --- |
| 门户地址 | 校园网络提供的认证入口 | 必填，优先使用 HTTPS |
| API 地址 | 门户认证接口地址 | 可先留空；指定时必须与门户同一主机 |
| AC IPv4 | 接入控制器地址 | 可先留空，由门户流程发现 |
| 载荷 IPv4 | 提交给门户的客户端地址 | 可先留空，由门户流程发现 |
| 本机源 IP | 发起实际网络连接的本机地址 | 通常留空，与“载荷 IPv4”分开 |

不要根据示例随意编造 AC 或客户端地址；从当前校园网络提供的信息中确认后再填写。服务器确认在线后，GUI 才显示无线认证成功。

门户地址和 API 中不得包含账号密码、令牌或会话凭据。地址中的公开接入点发现参数可以保留，例如 `wlanacip`、`wlanuserip`；不支持的参数会在认证前报告错误。

HTTPS 门户不会自动降级为 HTTP，API 也不能换到其他主机。校园门户若确实只提供 HTTP，需要显式勾选允许 HTTP；这会使账号密码在到门户的网络传输中暴露，见[无线门户与密码传输](security.md#无线门户与密码传输)。

## 多账号

- 切换账号：先停止认证，在账号下拉框中选择已保存的账号，再点击“认证”。
- 添加账号：在账号框输入新账号，填写密码和所需 IP，再点击“认证”。
- 修改密码：选中账号，输入新密码后点击“认证”。
- 删除账号：停止认证，选中账号，点击“删除”并确认。

删除账号只移除本机保存的记录，不会注销或删除学校提供的账号。保存位置、换电脑及恢复方法见[账号与隐私](security.md)。

## 托盘、停止和退出

认证成功或手动最小化后，窗口会隐藏到托盘，认证仍在继续。左键点击托盘图标，或从托盘菜单选择“打开”，可以恢复窗口。

在线会话转为等待网卡、重新认证或断开时，窗口会重新显示相应状态，核心继续按配置恢复连接。

“停止”会请求核心注销并停止本次认证；若核心没有及时退出，GUI 会结束自己启动的进程。关闭窗口或选择托盘菜单的“退出”，会停止认证并退出 GUI。GUI 不会按进程名称终止其他独立运行的核心。

## 自动启动和自动认证

“Windows 登录时启动”设置当前 Windows 用户的登录启动项，不需要管理员计划任务。

“打开 GUI 后自动认证”使用已选账号和当前认证模式开始认证。只勾选前一项会打开 GUI，但不会立即认证；只勾选后一项则需要先手动打开 GUI。

## 排查连接问题

1. 点击“环境自检”，先检查核心、网卡与抓包环境。
2. 确认模式、账号及实际校园网络相符；无线模式确认门户地址可信且属于当前网络。
3. 查看状态下方的日志。核心会按配置重试，GUI 不会因为出现一次错误就停止重连。
4. 如需向他人求助，点击“导出诊断”，按[分享诊断的说明](security.md#导出和分享诊断)检查内容。

自检可能列出未满足的条件并显示警告；这不等于检查程序崩溃。结果会保留在日志中，可以随诊断一起导出。自检通过只能说明相应本机条件可用，不能代替学校服务器认证成功。

## 高级：核心配置

大多数用户只需使用界面。核心的其他选项位于 `%LOCALAPPDATA%\drcom4scutGUI\core.yml`；修改前先停止认证，保留原文件，并参考[核心文档](https://github.com/SeaLoong/drcom4scut#readme)。不要在该文件填写账号密码，GUI 会提供本次认证所需的凭据。

GUI 没有单独的协议 profile 选择框。核心默认 `profile: legacy`；只有确认当前网络需要另一个兼容 profile 时，才在 `core.yml` 中调整 `profile`。不应把切换 profile 当作每次安装的必选步骤。

界面选择的认证模式、是否使用 UDP、是否允许 HTTP 以及填写的对应参数会显式传给核心。不要依赖 `core.yml` 把界面显示的有线模式改成无线模式，或绕过未勾选的 HTTP 许可。
